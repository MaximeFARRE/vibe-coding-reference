# VCR self-audit

19 November 2026 · Open · Local branch `feat/project-health-check` at `d53401da974bd4d242275a6c50591a1f845999bd`, with pre-existing edits to this directory's index and implementation status and an untracked trial note and `.DS_Store`.

**Recommendation.** Focus VCR on one useful RESCUE pass. It should help the user locate a problem, understand the evidence and choose the next verification. Use CHECK and RESCUE for two views of the same passive observations. Judge the first change by whether a fixture with a real, identifiable issue produces a concrete next action from one scan.

The method draws on two supplied documents outside the repository. `01_RETEX_PORTFOLIO_ENGINE_ET_PRINCIPES_VCR.md`, sections 4 and 7, suggests tracing realistic changes and checking consumers before removing code. `02_LITTERATURE_ET_HYPOTHESES.md`, sections 2 and 3, cautions against universal thresholds and unsupported savings claims. Their implementation proposals are reference material. Findings below come from the local VCR tree. The literature was not independently reviewed.

## Findings in order of impact

1. **Confirmed — CHECK and RESCUE share filesystem collection and split the interpretation.** `audit()` builds RESCUE checks and findings during a CHECK run, swaps in a separate checklist, returns a RESCUE run and lets `run_checks()` rename it and empty the findings. Node script keys are examined twice in the same block. A fixture with `"test": ""` made RESCUE report a test hint and suppress `tests-unknown`, while CHECK left `TEST-01` at `not_checked`. A Python fixture with `[tool.pytest.ini_options]` gave RESCUE a pytest hint that CHECK did not surface. On VCR itself CHECK found a CI YAML file but left `TEST-01` unchecked. The local suite independently ran 68 tests. **Simplify:** determine facts once, preserve the separate meanings of a declaration, a filename hint and an execution result, and have both commands use those facts. Keep the narrower distinction between a sensitive filename present in the inventory and a name tracked by Git. [Collector](../src/vcr/rescue.py#L131) · [CHECK projection](../src/vcr/check.py#L54)
2. **Confirmed — the quick/full switch is overwritten by a manifest path.** `audit(..., full=False)` assigns `full = repo / path` while reading manifests, then forwards it to `health_checks`. On a Node fixture with a declared test, the default and `--full` printed the same four execution rows, with `TEST-01-EXEC` marked `skipped`. The default on an empty directory produced no execution rows. The fixture's sentinel command never ran. **Simplify:** fix the variable collision and test both modes on the same fixture. Consider retiring the extra rows and flag only after deciding the public CLI contract. [Variable assignment](../src/vcr/rescue.py#L135) · [Mode forwarding](../src/vcr/rescue.py#L182) · [Execution rows](../src/vcr/check.py#L57) · [Existing tests](../tests/test_check.py#L38)
3. **Confirmed — IMPROVE adds a source-count gate before offering action.** A single RESCUE JSON on the Node fixture gave no proposal. Repeating the scan without changing the fixture gave an `architecture-doc` proposal. A CHECK JSON for the same target was refused with exit 2. The Python fixture already had an Architecture section in README, yet RESCUE emitted `architecture-doc` because only two filenames count. That narrow observation is documented and correctly qualified. Its promotion by repetition is a weak basis for deciding to do work. The import deduplicates a run ID, so two runs of the same state count separately. **Simplify or defer:** make one verified observation sufficient for a useful RESCUE decision. Keep the registry optional for genuine history and review its value before asking users to maintain one. [Filename rule](../src/vcr/rescue.py#L173) · [Import and identity](../src/vcr/improve_sources.py#L26) · [Proposal gate](../src/vcr/improve.py#L33)
4. **Confirmed — duplicate maintenance in evidence, decisions and CLI.** Adding a RESCUE finding currently requires a decision tuple from the renderer, then IMPROVE separately recognizes selected overlapping IDs and provides its own guidance. `tests-unknown` and `architecture-doc` repeat the same first action across both tables. Some additional IMPROVE rules have real consumers via explicit note markers. CHECK and RESCUE repeat run normalization and JSON preparation at different boundaries. Both feedback paths implement atomic JSON replacement independently, and the CLI repeats identical error handlers. **Merge selectively:** keep advice with its finding when it has the same intent and leave history-specific guidance with IMPROVE. Reuse existing write logic only if its safety and error behavior can be preserved. The report formats, output location protections, atomic file replacement and the distinction between finding feedback and registry status serve existing contracts. A generic workflow framework would add another concept without resolving the evidence split. [Finding construction](../src/vcr/rescue.py#L35) · [Advice tables](../src/vcr/report.py#L5) · [IMPROVE rules](../src/vcr/improve_rules.py) · [CHECK JSON and errors](../src/vcr/cli.py#L100) · [RESCUE JSON](../src/vcr/rescue.py#L194) · [Feedback write](../src/vcr/feedback.py#L43) · [Registry write](../src/vcr/improve_registry.py#L57)
5. **Confirmed — the CHECK launch kit still reads like active instructions.** Its five Markdown files, mission prompt and documentary JSON catalog total 408 lines. The kit README instructs readers to copy the old prompt. Its specification shows `--allow-project-commands`, which the current parser does not accept. The kit and catalog cross-reference one another. The packaged `src/vcr/catalog.json` is a different file, used by SOURCES. **Retired on November 19:** the launch kit and documentary catalog were removed. Their source references and outstanding proposals remain available in Git at `d53401d`. Keep `AGENTS.md` concise. It is currently 12 lines and already points to the README and status. [Current parser](../src/vcr/cli.py#L30) · [Packaged catalog](../pyproject.toml#L20) · [Agent instructions](../AGENTS.md)

## Keep, combine, retire or defer

- **Keep** the single CLI, bounded passive inventory, evidence and uncertainty, explicit outputs outside the target, existing schemas and documented reports for this first change. Protect Git and sensitive-file handling and run the existing fixture suite. `pyproject.toml` offers optional pytest for development, while CI uses `unittest`. Removing that extra is a low-value compatibility decision. [CI](../.github/workflows/ci.yml)
- **Combine** the test evidence path first. Keep the existing command names and output shapes through the first iteration. Fix the quick/full collision as part of the same bounded change. Test one report with a useful next verification and one ambiguous fixture whose uncertainty remains explicit.
- **Retire after approval** the CHECK bootstrap prompt and obsolete launch instructions. The documentary catalog and plan can move out of the active reading path once unique content and inbound links are checked. This gives an immediate documentation simplification without touching installed VCR.
- **Defer** extending the registry, adding native token imports and building the proposed architecture-health catalog. Consider a shorter START template, SOURCES as a static reference and TOKENS as an optional import only after checking who uses the CLI and saved formats. Current code and tests confirm those features work within their contracts. Usage remains `not_checked`.

Two other options were considered. A documentation-only reduction is low risk and reduces what an agent has to read, while the contradictory test evidence would persist. A replacement core might ultimately make sense if the project becomes a method plus a tiny collector, but maintaining parallel implementations or changing report contracts would cost more to evaluate at this stage. Improve one path in place and use its evidence to decide what to retire.

## Reproduction and limits

- **Inventory.** `git rev-parse HEAD`, `git status --short --branch`, `git rev-list --count HEAD`, `git rev-list --count --all`, `git ls-files`, `wc -l src/vcr/*.py tests/*.py`, and `git log --no-merges --format=%s HEAD` grouped by commit subject prefix. Markdown totals count working-copy lines for tracked paths at audit start. Uses and documentation links were searched with `rg`.
- **Fixtures.** `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -m unittest discover -s tests -q` passed 68 tests under Python 3.12.9 on macOS. That suite checks existing output contracts, including the two-report journey.
- **Targeted CLI reproduction.** In a temporary project containing only `package.json` with `{"scripts":{"test":""}}`, run `python3 -m vcr check --repo <project> --json` and save stdout outside the project. Run `python3 -m vcr rescue --repo <project> --out <new-dir>` twice with distinct output directories. Run `python3 -m vcr improve --project <project> --from <run.json> --out <new-dir>` with one RESCUE report, then both using repeatable `--from`, then with the CHECK JSON. Inspect `TEST-01`, RESCUE `checks` and `findings`, and `proposals.json`. The fixture stayed byte-identical through the scans. Separately, repeat CHECK and RESCUE on the Python fixture described above. For the mode bug, use `{"scripts":{"test":"touch marker"}}` and compare CHECK JSON with and without `--full`, then with an empty directory. No marker was created. All CLI reproductions used the same `PYTHONPATH` and bytecode setting as the suite.
- **Not checked.** External installations, downstream parsers or consumers, usage telemetry, work on Windows or Linux, remote CI, adversarial inputs and effect on future maintenance cost. No target code was executed. No timing or token savings are inferred. Web-service and database complexity are `not_applicable` to this runtime.
